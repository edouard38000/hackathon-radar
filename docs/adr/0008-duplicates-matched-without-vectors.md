# Duplicate listings are matched by rules in SQLite, not by vectors

The same Hackathon is often listed on several Sources. The engine merges Duplicate listings with plain rules in SQLite: the same official link (after stripping tracking parameters and `www.`, or pointing to the same Luma or Devpost event), or else the same start date and city with closely similar names. Pairs the rules can't settle go to the Agent along with the Candidates, since it reads those pages anyway. We considered semantic matching with embeddings: Neon with pgvector, as the Vesara Daily newsletter uses, would break ADRs 0001 and 0003 (hosted, data off the machine); a local `sqlite-vec` would still need an embedding model to pay for or download. A Hackathon has hard identifiers (link, date, city) that news stories lack, so rules plus the Agent are enough. Never announcing a Hackathon twice is separate: it is the Announced flag on the stored Hackathon.
