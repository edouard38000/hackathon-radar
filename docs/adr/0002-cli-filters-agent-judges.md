# The Rust CLI filters; a headless agent judges

Each Run is split in two. The Rust CLI does everything deterministic: it fetches the structured Sources (ICS calendars, the hackathonhub sitemap, the Devpost JSON), removes duplicates, applies the Profile rules it can check from data alone (dates, Countries, Train limit, Flight budget), looks up Fares, stores results and sends Alerts. It then hands the surviving Candidates to the person's own Agent, run headless: Claude Code (`claude -p`), Codex (`codex exec`), or any other coding agent through a command template, all behind one interface, using the person's existing subscription, with an API key only as a fallback. The Agent reads each event page and decides only what needs judgement: whether it is really a Hackathon, Eligibility, and whether it is Travel-funded. We chose this over one agent doing everything (how the personal version works) because it cuts the tokens each Run costs the person, and makes the rules testable and repeatable.

## Consequences

- **Fares come from the CLI, not the agent.** The CLI queries Google Flights prices through the person's own SerpApi key (its free tier covers about 175 lookups a month). The airline and GDS APIs are closed to individuals: Amadeus Self-Service shut down in July 2026, Kiwi Tequila is invite-only, Skyscanner refuses non-commercial users, and Duffel needs a business. Without a key, the agent estimates the fare from web search and the CLI stores it as an Unverified fare.
- **Train times and nearest airports** are estimated by the agent once per destination city, cached per Home, and correctable by the person.
