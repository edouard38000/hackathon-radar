# The agent can only search and read; the CLI does all writing

The person's Agent runs headless with web search and page reading only: no shell, no file writes, nothing else. It returns its judgements as JSON matching a schema the CLI provides, and the CLI validates and stores them. Each Run is capped by a number of agent steps rather than dollars, because most people use their subscription, where a dollar cap means nothing. A Run makes at most two Agent requests, judging (capped by `max_turns`) and travel estimates (capped by `travel_max_turns`, default 15). The personal version let the agent write the Google Sheet and calendar directly; we don't, because strangers will run this unattended every week on their own machines, and an agent that reads arbitrary web pages must not be able to act on anything it reads there.

How each Agent is held to this:

- **Claude Code**: `claude -p --permission-mode dontAsk --tools WebSearch,WebFetch --allowedTools WebSearch,WebFetch --strict-mcp-config --setting-sources "" --max-turns <n> --output-format json --json-schema <schema>`. Without the extra flags, the person's own user settings (allow rules such as `Bash(...)`), hooks and MCP servers would still apply: `--tools` makes web search and page reading the only tools that exist, `--strict-mcp-config` with no `--mcp-config` loads no MCP servers, and `--setting-sources ""` loads no user, project or local settings, so no allow rules or hooks (the person's sign-in still works, which is why `--bare` is not used).
- **Codex**: `codex exec --sandbox read-only --skip-git-repo-check --ephemeral --ignore-user-config --ignore-rules -c approval_policy="never" -c web_search="live" -c features.shell_tool=false -c features.view_image=false --output-schema <schema file> --json -`. A read-only sandbox alone still gives Codex a shell that can read the whole disk, so `features.shell_tool=false` and `features.view_image=false` remove the command and local-image tools; `--ignore-user-config` loads none of the person's `config.toml`, so none of their MCP servers, sandbox or approval settings, and `--ignore-rules` none of their execpolicy rules (the person's sign-in still works); `approval_policy="never"` means nothing is ever escalated; `web_search="live"` turns on live search (what `--search` does); `--ephemeral` keeps no session files and `--skip-git-repo-check` lets it run in an empty, non-Git directory. Unverified against a real Codex CLI; the adapter stays behind an explicit experimental opt-in until a recorded run confirms these flags.
- **Any other coding agent**: a command template in the Profile. The setup guide states the read-only requirement, and the CLI rejects output that doesn't match the schema.

Never use `bypassPermissions`, `--dangerously-skip-permissions` or a writable sandbox.
